# 루프 2 설계서 — 조언 수용량(WOA) × AI 확신도 표시

> 상태: **작성 중** (설계 질문 모드). 정웅 님 답을 그대로 옮긴 기록이다. 다섯 칸이 다 차면 함수 목록 + 데이터 흐름 + 의사코드로 정리한다.

## 연구 질문과 가설 (10/18 초안)
- 질문: AI 조언에 확신도를 표시하면 과의존을 막을 수 있을까?
- 가설: 확신도 표시 조건이 미표시 조건보다 **틀린 조언**에 대한 WOA가 낮을 것.
- 조작: 확신도 수치(A%) 표시 여부 — **참가자 간** (10/21 결정, 이유: 한 번 본 확신도가 미표시 조건에도 남는 비대칭 이월)
- 측정: WOA = (최종 − 초기) / (조언 − 초기)

## 설계 전 예측 (10/3)
- 함수 6개: 화면 띄우기, 끝내기, 기록, 최종값 저장, 다음 화면, AI 답안 제공
- 한 시행 기록값 5개
- 가장 오래 막힐 칸: 1번(화면과 행동), 그다음 4번(호출 순서)

## 빌드 전 예측 (10/31, 3번 칸 시작 전)
- 함수 개수: 15개 (이름은 안 적음)
- WOA 계산 시점: 끝나고 분석 때. "시행 도중에 계산하면 값이 계속 바뀌잖아. 굳이 중간에 할 필요가 있나?"
- 확신도 숫자가 만들어지는 시점: 실험 시작 전. "기본 설정을 정해둬야겠지."

## 1. 화면과 행동 — 일단 닫음 (10/3)
- **문제 재료**: 대충 짐작할 수 있는 숫자 문제 (가격·길이·연도 등).
  - 정답을 완전히 알면 WOA가 지식을 재고, 전혀 모르면 무지를 잰다 → 둘 다 신뢰를 못 잰다.
- **AI 조언**: 실험자가 미리 정한 숫자(스크립트 오라클). 일부는 일부러 틀리게 → 맞는/틀린 조언별 WOA를 나눠 봐야 **적절한 의존**을 판단할 수 있다.
- **화면 흐름** (4문항 묶음):

| 화면 | 보이는 것 | 하는 행동 |
|---|---|---|
| ① 초기 추정 | 문제 4개, 문제마다 슬라이더 | 슬라이더 조정 → 다음 |
| ② AI 조언 | 문제별 AI 추정값 (확신도 = 조작 변수) | 읽기 → 다음 |
| ③ 최종 추정 | 문제별 **초기값 + AI 조언** 표시, 슬라이더 | 슬라이더 조정 → 끝내기 |
| ④ 저장 | 결과 | 저장 |

- ③에서 초기값을 보여주는 이유: 숨기면 "기억이 흐려져서 바뀐 몫"과 "조언 때문에 바뀐 몫"을 구분할 수 없다.
- ③ 슬라이더 손잡이 시작 위치 = **초기 추정값** (안 건드림 = 내 추정 유지 → WOA 0. 가운데에 두면 기본값이 의미 없는 WOA를 만든다).

**보류 목록**
- 입력 방식 (슬라이더로 잠정 결정) / 조언 형식(숫자만 vs 설명) / 문제 개수
- 추가 측정: 답안 확신도, AI 신뢰도
- 저장 방식: CSV 다운로드 vs 복사·붙여넣기 (Fitts 때 다운로드 문제)
- 다음 버튼 활성화 조건 (입력 후 vs 일정 시간 후)

## 2. 한 시행 기록값 — 진행 중
- 성의 없는 응답 구분용: 화면에서 넘어가기까지 걸린 **시간**, 슬라이더를 **움직였는지 여부**(자기보고 슬라이더도 기본값 문제를 똑같이 겪는다).
- 질문 2-2: CSV 한 줄 = 한 문항의 한 시행일 때, (1) WOA 계산 (2) 맞은/틀린 조언별 WOA 비교 (3) 성의 없는 응답 거르기를 하려면 어떤 열이 있어야 하나?
  - 10/24 답 (1차, 6개): 확신도 표시 여부 & 수치, 참가자의 응답값, AI 답안 맞는지 여부, 응답 시간, AI가 제공한 답안
  - 2-3 (10/24): 응답값은 **초기 추정 + 최종 추정 두 열**로 나눠야 한다. 응답 시간도 **화면별로** 따로 기록해야 할 듯.
  - 정웅 님 질문: "성의 없음의 기준이 뭐지?" → 정답 없음, 연구자가 **데이터 보기 전에** 정하는 규칙(사전등록 취지).
  - 2-4 (10/24): "안 움직임"만으로 거르면 오래 고민하고 유지한 사람도 걸러진다. 사람마다 판단 시간이 달라서 시간 기준도 고민.
    - 참고: 공식 표준은 없음. 설문 연구의 흔한 절대 기준 = 문항당 2초 미만(Huang 등 2012), 상대 기준 = 표본 중앙값의 일정 비율 미만.
  - 2-5 (10/24): "상대 기준이 더 정확할 듯". 규칙 초안 = ③ 화면 시간 **2초 이하 + 슬라이더 안 움직임** → 거름 / **30초 이상 + 안 움직임** → 거름. 적용 결과: 아만 걸러짐.
    - 미해결: 상대 기준을 선호한다고 했는데 규칙 숫자는 절대 기준(2초·30초) → 나중에 하나로 정리
  - 2-6 (10/24): 30초 규칙은 "문제를 안 풀고 가만히 있는 사람"을 노렸지만, 오래 고민한 사람과 기록만으로 구분 불가 → **폐기**. 이유: 아예 안 하는 사람보다 너무 빨리 대충 하는 사람이 더 많을 것.
    - 현재 거르기 규칙: ③ 화면 **2초 이하 + 슬라이더 안 움직임** → 거름 (절대/상대 기준 정리는 남음)
  - 2-7 (10/24): 4문항 한 화면이면 네 줄 모두 화면 시간(40초)이 찍혀 대충 넘긴 문항이 안 걸러진다 → 바꾼다면 **한 화면에 문제 하나씩**.
    - 정웅 님 질문: WOA 연구가 원래 시간으로 거르나? 통계적 이상치만 거르지 않나? → 고전 WOA 연구의 정리는 주로 **WOA 값 자체** 기준(0~1 밖 값 자르기, 조언 = 초기값 시행 처리). 시간·주의 확인 문항은 온라인 실험에서 덧붙이는 편. (Claude 기억 기준, 원문 미확인)
    - 결정: 시간·슬라이더 움직임은 **기록은 해 두고**, 거르기 규칙은 WOA 값 기준과 함께 나중에 확정
    - 보류: "한 화면에 한 문제"가 문항마다 초기→조언→최종을 끝내는 방식인지, 초기 4개 → 조언 4개 → 최종 4개를 한 문제씩 보여주는 방식인지
  - 2-8 (10/24, 미션의 추가 예측): 조언 = 초기값이면 WOA는 0으로 나누기 → **계산 불가**, 신뢰에 대해 아무것도 알려주지 않음. 막는 법 = 조언이 초기 추정과 같으면 if문으로 **±10** 조정.
    - 이 해결책은 1-5("조언을 미리 정해 둔다")를 "초기값에 따라 조언이 바뀐다"로 일부 바꾼다 → 3번 칸(조언을 만드는 함수가 초기값을 알아야 함)에 영향
  - 2-9 (10/24): 초기 150 / 조언 160 / 최종 155 → WOA 0.5 — "거의 무시"라는 마음과 안 맞음 (차이가 작으면 손떨림이 WOA를 크게 흔듦). 조정 폭은 **초기값의 비율**로. 이유: 문제마다 답의 크기(단위)가 다르다.
  - 2-10 (10/24): 초기값 0이면 ±20%도 0 → 여전히 계산 불가. 해결 = 슬라이더 범위를 0보다 큰 값부터 (예: 100~600).
    - 보류: 슬라이더 범위 자체가 정답 힌트(앵커)가 될 수 있음 → 문항마다 범위를 어떻게 정할지, 정답이 범위 가운데에 오지 않게 할지
  - 2-11 (10/24) 열 목록 1차 (10개): 초기 응답값, 조언 이후 응답값, 확신도 표시 여부, 확신도 수치, AI 조언 (맞음) 여부, AI 조언값, 슬라이더 범위, 소요 시간, 문항 번호, 슬라이더 움직임 여부
  - 2-12 (10/24): **참가자 번호** 열 추가 (11개). 확신도 표시 여부(참가자 단위 조건)는 줄마다 넣지 말고 **다른 곳에 따로** — 참가자를 알면 조건도 아니까.
  - 2-13 (10/24): 따로 적으면 분석 때 참가자를 조건별로 나누는 단계가 하나 더 필요하고, 메모를 잃으면 누가 어느 집단인지 모른다. 그래도 "확신도 수치 열이 있으니 조건을 알 수 있지 않나?"
  - 2-14 (10/24): 미표시 조건에서도 확신도는 **미리 정해 두고 기록만**(화면에 안 보임) — 빈칸이면 두 조건 간 "확신도별 WOA" 비교가 불가능. 대신 수치만으로는 조건을 알 수 없으므로 **확신도 표시 여부를 줄마다 넣는다**.

**2번 칸 결과 — CSV 열 목록 (한 줄 = 한 참가자의 한 문항, 12개)**
1. 참가자 번호 2. 문항 번호 3. 확신도 표시 여부 4. 확신도 수치(미표시 조건도 기록)
5. 초기 응답값 6. 최종 응답값(조언 이후) 7. AI 조언값 8. AI 조언 맞음 여부
9. 슬라이더 범위 10. 소요 시간 11. 슬라이더 움직임 여부
- (예측 5개 → 실제 11~12개. 슬라이더 범위를 최소·최대 두 열로 나누면 12개)
- 2-15 (10/24, '틀린 조언' 기준): 기준은 **문제 종류에 따라 다르다** — 연도처럼 %오차가 안 맞는 문제가 있음 → 우선 **오차가 허용되는 문제**(가격·길이·개수 등)로 한정. 규칙 초안 = 정답과 **5% 이내 맞음, 그 이상 틀림**. 애매한 조언은 빼고 확실히 구분되는 조언만 쓴다.
  - 2-16 (10/24): 4%와 6%는 참가자에게 비슷하게 느껴짐 → 빼는 구간을 둔다. **3% 이내 맞음 / 20% 이상 틀림 / 그 사이는 조언으로 쓰지 않음.**
    - 선택안: 맞는 조언은 **정답 그대로** 제시 → 그렇다면 틀림 기준을 15%로 낮춰도 됨
  - 2-17 (10/24): 정답 1000 = 초기 1000 = 맞는 조언 1000 → +20% 조정 시 1200 = **틀린 조언**으로 바뀜(미리 적은 "맞음"과 충돌). → 조정 정도를 바꿔야 하고, 맞는 조언을 정답 그대로 주는 안은 **폐기**, 맞는 조언에 **3~5% 여유**.
    - 미해결: 3~5%는 2-16의 "3% 이내 맞음 / 3~20% 사용 안 함"과 겹침
  - 2-18 (10/24): 맞음 기준 **3%로 확정**. 조언 = 초기값일 때 조정 규칙을 **정답 기준**으로 다시 씀:
    - 맞는 조언 → 정답 ±3% 안에서 다른 값으로 (예: 정답 1000, 조언·초기 980 → 1020)
    - 틀린 조언 → 정답과 20% 이상 차이가 유지되게
    - 결과: 조정하려면 프로그램이 **정답**을 알아야 함 → 문항 데이터에 정답 필요 (2번 칸 열린 질문 하나 해결)

- 2-19 (10/24, 확신도 보정): 정확도 75%일 때 (A) 전부 75% / (B) 맞음 90%·틀림 30% / (C) 맞음 75%·틀림 90% 중, 확신도로 틀린 조언을 거를 수 있는 건 (B)뿐.
  - (B)로 가설이 맞게 나와도 "표시 자체가 과의존을 막는다"가 아니라 "수치가 판단을 쉽게 해줬다"일 수 있음. (C)면 표시가 **역효과**일 수도.
  - 정웅 님 깨달음: "확신도만 보여주면 다시 생각하게 돼서 과의존이 줄 거라고 막연히 생각했다." → 표시 효과는 **확신도와 정답의 관계(보정)**에 따라 달라짐 = 보정 양상이 **조절 변수**(U2).
  - 2-20 (10/24): 참가자는 많아야 4~5명(잘하면 10명) → (가) 집단당 1~2명, (나) 집단당 1명 이하. 루프 목표 = 통계적 결론이 아니라 **실험 설계·구현 학습** → **(가) 한 양상으로 고정** 결정: 잘 보정된 AI. 연구 질문을 "**잘 보정된** 확신도를 보여주면 틀린 조언 WOA가 낮아지나?"로 좁힘.
    - 참고: 집단당 1~2명이면 집단 차이는 개인차(잡음)와 구분이 안 됨 → 결과는 "파이프라인이 돌아가는지" 확인용. (B)·(C) 비교는 다음 루프 후보로.
  - 2-21 (10/24): (B)처럼 90/30으로 딱 갈리면 "숫자 두 개 구분" 과제가 됨(자동 판단 가능). → 확신도 범위 **맞는 조언 70~90% / 틀린 조언 55~75%, 일부 겹치게**. 이유: 안 겹치면 패턴만 읽어 숫자로 구분해 버린다.
    - 확인: 평균 확신도 ≈ (12×80 + 4×65)/16 ≈ 76% ≈ 실제 정확도 75% → 전체적으로 **보정됨**, 맞는 조언이 대체로 더 높아 **해상도도 있음**(완벽하진 않음).

**확신도 보정 — 결정 (10/24)**
- 보정 양상은 하나로 고정: 잘 보정된 AI (정확도 75%, 맞음 12 / 틀림 4)
- 확신도: 맞는 조언 70~90%, 틀린 조언 55~75% (70~75% 구간 겹침)
- 두 조건 모두 같은 확신도를 미리 정해 두고, 표시 조건에서만 화면에 보임

  - 2-22 (10/24): 틀린 조언 WOA 0.6→0.3 이어도 맞는 조언이 0.7→0.2면 가설은 맞지만 **적절한 의존이 아님** — 확신도를 보고 AI 조언을 전반적으로 안 받아들임. 덧붙인 가설 = "표시/미표시 조건의 WOA 차이가 **맞는 조언보다 틀린 조언에서 더 클 것**" (상호작용 가설)
  - 2-23 (10/24): 틀린 0.6→0.2(차이 0.4) / 맞는 0.7→0.5(차이 0.2)면 상호작용 가설은 맞지만, 맞는 조언도 덜 받아들였으니 **성공 아님**. → 맞는 조언 가설을 따로 둔다: "맞는 조언에서는 표시 조건 WOA가 미표시 조건보다 **높다**."

**가설 — 결정 (10/24)**
- H1: 틀린 조언에서 확신도 표시 조건의 WOA가 미표시 조건보다 **낮다**.
- H2: 맞는 조언에서 확신도 표시 조건의 WOA가 미표시 조건보다 **높다**.
- (H1 + H2 = 적절한 의존. 표시가 조언을 전반적으로 덜 받아들이게만 만들면 실패로 본다.)

  - 2-24 (10/24): 조언 맞음/틀림 = **참가자 내** → 전체는 **혼합 설계** (확신도 표시 간 × 조언 정오 내). 틀린 조언을 앞에 몰면 신뢰가 떨어져 이후 맞는 조언 WOA도 낮아질 것. → 섞는다(완전 무작위 or 맞는 문항 사이사이). 걱정: "순서를 달리한 게 또 다른 요인이 되면?"
    - Claude 설명: 사람마다 무작위로 섞으면 순서 효과가 조건과 묶이지 않음 → 편향(교란)이 아니라 **잡음**이 됨(U4). 단 인원이 적으면 우연히 나쁜 순서(틀린 4개가 앞에 몰림)가 나올 수 있어 "제약 있는 무작위"도 선택지.
    - 정웅 님 안: "배치 순서는 비슷하게 하되 문제를 달리 해도"
  - 2-25 (10/24): 조건마다 문제 세트가 다르면 차이가 확신도 때문인지 문제 때문인지 알 수 없다 → **교란**(조건별 문제 세트 교란 — 이번엔 잡아냄). 정웅 님 원래 뜻은 다른 것이었음: **맞음/틀림 자리 패턴(예: 맞-맞-틀-맞)은 고정**하고, 같은 범주 안에서 **문제의 순서만 섞는다**(맞는 조언 문제 1 2 3 → 3 1 2). 두 조건 모두 **같은 16문항** → 안전.
    - 한계(기록): 어떤 문제가 틀린 조언을 받는지는 모두에게 같음 → 틀린 조언 문제가 우연히 더 어려우면 "맞음 vs 틀림" 비교에 문제 난이도가 섞임. 두 조건 비교(H1·H2)에는 영향 없음. 인원이 적어 이번엔 감수.

**순서·설계 — 결정 (10/24)**
- 혼합 설계: 확신도 표시(참가자 간) × 조언 맞음/틀림(참가자 내)
- 16문항은 두 조건 모두 동일. 맞음/틀림 자리 패턴은 고정(틀린 조언은 앞에 몰지 않고 사이사이), 같은 범주 안에서 문제 순서만 사람마다 섞는다

**'틀린 조언' 기준 — 결정 (10/24)**
- 문제 재료: 오차를 %로 따질 수 있는 문제(가격·길이·개수). 연도처럼 %가 무의미한 문제는 제외
- 정답과 **3% 이내 = 맞는 조언 / 20% 이상 = 틀린 조언 / 그 사이는 사용 안 함**
- 조언 = 초기값이면 범주(맞음/틀림)를 유지하는 쪽으로, 정답 기준으로 조정
