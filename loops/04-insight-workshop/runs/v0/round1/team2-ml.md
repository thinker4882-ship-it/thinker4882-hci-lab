## 1. ML 비유는 어디까지 맞고 어디서 깨지는가
**맞는 부분**: 추측 → 정오 신호 → 내부 표상 조정 → 반복. 이 구조는 지각 분류에서 실제로 작동한다. 가르치려는 것이 "특징 → 범주" 매핑이고, 말로 못 할 만큼 특징이 많고 미세하기 때문이다.

**깨지는 부분 4가지**
1. **사람은 파라미터를 직접 못 고친다.** 경사하강법은 오차를 원인 파라미터로 정확히 배분(credit assignment)한다. 사람은 "틀렸다"를 듣고도 어느 단서를 고쳐야 하는지 모른다. 그래서 사람에게는 정오만으로는 느리고, 주의를 단서로 유도하는 장치가 병행돼야 한다(Horsey 해석과 일치).
2. **ML은 표본이 수백만, 사람은 수백.** 사람은 표본 효율이 높은 대신 한 번의 오답에 감정·자존감이 반응한다. 학습률을 올려도 손실이 발산하지 않지만, 사람은 연속 오답이면 학습을 그만둔다(이탈이 발산에 해당).
3. **손실함수가 고정돼 있지 않다.** ML은 목적함수를 설계자가 정한다. 학습자는 "무엇이 좋은 것인가" 자체를 배우는 중이다.
4. **전이.** ML 모델은 학습 분포 밖에서 무너지고 사람은 개념으로 일반화한다. 반대로 사람은 "병아리 100마리를 맞힌 것"을 "병아리 감별을 이해한 것"으로 착각한다.

## 2. (가) 답이 분명하지 않을 때: ML이 쓰는 학습 신호
ML은 정답이 없는 문제에서 이런 신호를 만든다.

| ML 기법 | 신호 | 사람 교육으로 옮기면 |
|---|---|---|
| 선호 비교(RLHF) | A와 B 중 어느 쪽이 낫나 | 학습자의 글/풀이 두 개 중 나은 쪽 고르기 |
| 보상 모델 | 비교 데이터에서 점수 함수 추출 | 여러 전문가의 비교 판정을 모아 "좋은 글의 기준"을 추정 |
| 자기 일관성/자기 대국 | 정답 대신 내부 모순·승패 | 학습자가 쓴 두 주장의 충돌 지적 |
| 레이블 잡음 처리 | 라벨이 틀릴 수 있다고 가정, 다수 합의·불일치 탐지 | 전문가 간 불일치 자체를 학습 자료로 제시 |

**비자명한 통찰 1 — "절대 평가 불가"와 "상대 비교 가능"은 다르다.** 글쓰기·독서 해석처럼 정답이 없어도 "둘 중 어느 쪽이 낫다"는 판단은 사람이 일관되게 한다. RLHF의 핵심은 정답이 아니라 비교로 신호를 바꿨다는 점이다. 교육으로 옮기면 병아리 감별의 "맞다/틀리다"가 "스승이라면 어느 쪽을 골랐을까"로 바뀐다. 이때 학습자는 정답 대신 **전문가 선호의 분포**를 맞히는 훈련을 한다. 이것은 가설이며 검증된 교육 효과가 아니다(미확인).

**비자명한 통찰 2 — 전문가 간 불일치는 잡음이 아니라 지형이다.** ML에서는 라벨러 불일치를 잡음으로 보고 걸러내는 게 보통이다(confident learning 계열, 출처 미확인). 그러나 정답이 불분명한 영역(독서 해석, 설계)에서는 불일치가 "여기가 진짜 쟁점"이라는 신호다. 시스템이 학습자에게 일부러 합의 구간(쉬운 문제)과 불일치 구간을 구분해 보여 주면, 학습자는 "정답이 있는 문제"와 "정답이 갈리는 문제"를 구분하는 메타 능력을 얻는다. 병아리 감별 모델은 이 구분을 아예 못 가르친다.

## 3. (나) 통하는 영역과 안 통하는 영역의 기준
네 기준으로 판정하는 것을 제안한다.
1. **피드백 지연**: 결과가 즉시 오는가(병아리: 즉시, 독서 이해: 수 주~수 년 뒤). 지연이 길수록 신호가 약해진다.
2. **라벨 신뢰도**: 정오 판정자 간 일치율이 높은가. 낮으면 단일 정답 피드백은 오히려 해롭다.
3. **단서 차원**: 진단 단서가 지각적·저차원(암수, 비행기 실루엣)인가, 구조적·고차원(논증의 타당성)인가.
4. **표본 반복성**: 비슷한 사례를 수백 번 접할 수 있는가.

1·2·4가 높고 3이 "지각적"일수록 시행착오가 잘 통한다. 판독 영상, 코드 냄새 식별, 오류 유형 분류, 외국어 발음 구분이 여기에 가깝다. 안 통하는 쪽은 개념 이해, 창작, 윤리 판단, 장기 전략이다. 이 영역에서도 "지각적 하위 기술"(예: 좋은 논증과 나쁜 논증을 한눈에 가려내는 감각)만 분리해 시행착오로 훈련하는 것은 가능하다.

**비자명한 통찰 3 — 시행착오는 능력을 만들지만 설명 능력은 만들지 않는다.** 감별사 제자는 스승처럼 설명 못 하는 전문가가 된다. 이는 교육 시스템 입장에서 위험이다. 암묵지 학습자는 자신이 왜 맞히는지 모르므로 자기 오류를 자가 점검할 수 없다. ML의 해석가능성 문제와 동일하다. 따라서 시스템은 시행착오 후에 "모델이 학습자의 판단에서 추출한 단서 후보"를 보여 주는 해석 단계를 포함해야 한다(예: 학습자가 맞힌 샘플 중 공통 특징을 후보로 제시하고 학습자가 확인). 설명을 먼저 주면 실패한다(비행기 사례)는 점과 모순되지 않는다. 순서가 "시행착오 → 사후 설명"이다.

## 4. (다) 구축 설계 (ML 기법 → 시스템 부품)
- **능동 학습 → 문제 선택기**: 학습자의 현재 판단이 가장 불확실한 사례(결정 경계 근처)를 우선 출제. Settles 서베이의 불확실성 샘플링에 해당.
- **커리큘럼 → 난이도 스케줄**: 쉬운 대비 사례로 시작해 점차 미세한 차이로. 단 사람은 이탈 위험이 있어 정답률 70~85% 근처 유지 같은 목표를 둔다(수치는 내 가정, 출처 미확인).
- **혼합 제시(interleaving)**: ML의 셔플된 미니배치와 같은 발상. 범주를 섞어 내는 것이 변별 학습에 유리하다는 인지과학 주장이 있으나 이번 검색에서는 미확인.
- **선호 비교 모듈**: 정답이 갈리는 영역에서는 "A vs B" 비교 + 전문가 판정 분포 공개.
- **오류 로그 = 학습자 모델**: 학습자의 혼동 행렬(어떤 범주를 어떤 범주로 착각하나)을 쌓아 출제와 사후 설명의 근거로 쓴다.
- **전이 점검**: 학습 때 쓰지 않은 분포의 사례(예: 다른 농장의 병아리)로 주기적 테스트.

## 5. 일주일 안에 시험해 볼 구현물
1. **"둘 중 뭐가 더 나은 요약?" 비교 훈련기** — 책 한 단락에 대한 요약 두 개를 보여 주고 고르게 한 뒤, 사전 확보한 전문가(또는 LLM 다수결) 선호 분포를 공개한다. 일주일간 일치율 변화와 "갈리는 문제를 갈린다고 알아챘는지"를 기록.
2. **혼동 행렬 기반 오류 유형 감별기** — 독서 오류(주장/근거 혼동, 인과/상관 혼동 등) 문장 100개를 라벨링해 두고, 학습자의 혼동 쌍을 가장 자주 틀리는 쪽으로 출제하는 능동 출제 단일 HTML. 사후 설명은 학습자 정답 문장의 공통 특징을 보여 주는 한 줄.
